Hybrid Reasoning Agents：隐空间里想，文本里动手↗

elvis @omarsar032.4万 粉丝10月15日 05:52长帖

Stanford / Together 等提出：今天的 LLM agent 每一步推理都要写成文本才能搜、跑代码或行动，贵且慢。他们让模型在隐空间内部推理，只在调用工具或给出答案时切回文本；小模块 HybridLink 负责模式切换，工作记忆同时保存两类上下文。工具调用仍是明文，隐步骤也可检查。训练先 SFT 教会用 HybridLink，再 RL 优化何时切换。

核心要点

  • 动机：逐步文本推理吃 token、拖时延
  • HybridLink 在隐推理 ↔ 文本工具/答案之间切换；工作记忆跨轮
  • 两阶段：SFT 对齐接口，再 RL 学切换策略
  • 工具调用保持可读文本，便于审计

为什么推荐你在搭 Agent harness，对「推理要不要全部落成 token」正敏感；这篇直接给可检视的折中结构。

对你的帮助设计本地/低成本 agent 时可参考：内部想、对外才说话，省调用费并保留工具链可观测性。

AutoEnvScaling：让模型自己造 RL 环境再变强↗

elvis @omarsar032.4万 粉丝10月15日 04:29教程

微软等展示：把环境设计交给在终端里干活的 proposer，根据被训模型的 rollouts 生成新 RL 环境，再进入下一轮。Qwen3.6-35B-A3B 在 Terminal-Bench 2.1 从 41.1 提到 53.3。在终端里构建环境，有效环境比例可比纯 prompt 高至 25 倍，单有效环境成本低约 75%。

核心要点

  • proposer 在真实终端观察 rollouts → 生成下一轮环境
  • 终端造环境 ≫ 纯提示词造环境（有效率 ×25，成本 −75%）
  • 可用更强模型（GPT-5.6-sol / Opus 5）当 proposer 带弱模型
  • 闭环：新环境 → 新 rollouts → 再设计

为什么推荐RL 环境数据是你关注的稀缺品；「自动扩环境」比再堆人工题库更贴近工程。

对你的帮助自建 terminal/agent 评测时可借鉴 proposer+rollout 闭环，少手写环境。
