Google 开源 Harness²：让 Agent 自己改 Prompt/Skill/Memory，反复试出更好配置↗

Xudong Han @Xudong074529101.4万 粉丝10月18日 18:45

推荐原因直接对应你平时调 Claude/Codex harness 的痛点，值得收藏仓库并挑一个任务试跑。

做 Agent 的人大部分时间不是在换模型，而是在反复调 harness——包在模型外面的系统提示词、工具说明、记忆、Skill 和子 Agent。Google Research 开源的 Harness² 想把这件苦差事交给 Agent 自己：它不训练模型、不改权重，而是针对一个具体任务提出几种 harness 改法，实际跑一遍、比较各自的执行过程，再把有用的改动合成新配置，并把有证据支持的经验存下来留给以后的任务。Xudong 前几天解读过它的论文，这次推荐的是开源代码；AIGCLINK、Akshay、ai_for_success 同一天也介绍了它。论文报告的提升不小，但试错的额外成本和经验能不能迁移到新任务，作者认为还要再看。

核心要点

  • Harness 指包在模型外面的那一层：系统提示词、工具说明、记忆、Skill、子 Agent、脚本和插件。Harness² 不训练模型、不改权重，只让 Agent 自己改这一层。
  • 做法是一个三步循环（Propose–Probe–Compose）：先提出几种改法，再让不同配置实际跑同一个任务、对比执行过程，最后把有效的改动合并成更适合这个任务的配置。
  • 任务做完后，它把用到的配置和「有执行证据支持」的改进经验存下来，下次遇到类似任务先参考——相当于把人工调参时写不下来的经验自动积累起来。
  • 论文在 WorkBuddy-Bench 上单轮优化最高提升 11.5 分；Xudong 提醒，反复试错要多花多少 token、经验换到新任务上还管不管用，都还没充分验证。
  • 据 AIGCLINK 的拆解，它兼容 OpenCode、Codex 作为执行器，能优化系统提示词、护栏、记忆、工具说明、子 Agent、Skill、脚本、插件八类组件。

论文：约 16 个 memory token 打赢全上下文，源文档用量少约 108 倍↗

elvis @omarsar032.5万 粉丝10月19日 01:59长帖

推荐原因做 Agent 长期记忆时，可当「压缩表征 vs 塞全文」的硬对照。

Agent 要「记住」读过的资料，常见做法是把全文塞进上下文，或者用检索把相关段落找回来，两种都很费 token。Omar 介绍的这篇论文换了个思路：资料只编码一次，存成模型能读懂的向量；每次提问时，由一个训练过的小模块从整个资料库里挑出相关信息，压进 16 个「记忆 token」交给一个不改权重的大模型。结果是在事实核查测试 FactKG 上，它比把全文放进上下文还准，而源文档占用的 token 少了约 108 倍；拿 Agent 自己的经历当资料库时，文字冒险游戏里的成功率也提高了。Omar 认为这是让模型在长期使用中持续积累知识的一条路。

核心要点

  • 论文提出 Latent Semantic Memory（潜在语义记忆）：文档只编码一次，存成可复用的向量；每次提问时，一个训练过的模块从整个资料库里挑出相关信息，压进 16 个「记忆 token」交给一个不改权重的大模型。
  • 在 FactKG（一个事实核查问答测试）上，16 个记忆 token 的准确率是 84.33%，高于把全文塞进上下文的 80.43%，而源文档占用的 token 少了约 108 倍；在 8 个基准里有 5 个胜过 Mem0、MemoRAG 等现有记忆方案。
  • 它也能当 Agent 的记忆：在文字冒险游戏环境 TextWorld 里，把 Agent 自己走过的历史当资料库，成功率从 18.6% 提高到 24.2%，重复回到已去过房间的次数也更少。
  • Omar 的判断是，这条路可能让不改权重的模型在长期交互里持续积累和使用知识，适合做「持续学习」的 AI 系统。

评论总结

  • 疑问Rozov_Artem 认为 108 倍省 token 是标题，真正的问题是更新成本：源文档一改，是要把整个记忆重新编码，还是能局部修补？这决定了它能不能用在每次会话都在变的 Agent 记忆上。
  • 分歧fuzzystripe 提醒格式变了：记忆从文字变成 16 个只有特定模型读得懂的 token，换模型或导出时就只剩一堆数字，「把记忆带走」会变得很难。
  • 亮点iPuneetSingh 和 Cyphrexio 建议先拿自己已知答案的问题测一遍：压得这么狠的记忆会悄悄丢掉个别关键事实，而且你不知道丢的是哪一条。

Ben Horowitz 团队实测：顶级模型写的网站一捅就漏，厂商却说「提示词写错了」↗

AYi @AYi_AInotes7.4万 粉丝10月18日 21:51长帖

推荐原因让 Agent 碰真数据前，用这条检查你的权限与熔断设计。

AYi 转述了 Ben Horowitz（硅谷风投 a16z 创始人之一）在访谈里讲的一次测试：他们让一个 Agent 用顶级闭源模型给宠物店做网站，写出来的代码漏洞很多；接着让另一个 Agent 去攻击，它很快顺着漏洞进去，把客户数据全部拿走。团队把问题反馈给模型厂商，对方却回复「你们提示词写错了」。AYi 的看法是，今天说的「安全对齐」大多停留在教模型说得体的话，一旦 Agent 能调用工具、读写数据库，靠几句提示词防风险就等于裸奔；出了事，厂商把工程缺陷说成用户的提示词问题，责任最后落在签字上线的人身上。他据此总结了三条落地教训。

核心要点

  • 测试过程：Ben Horowitz 团队让一个 Agent 用顶级闭源模型给宠物店搭网站，代码漏洞很多；再让另一个 Agent 去攻击，它顺着漏洞进去，把客户数据全部拿走。
  • 他们把问题反馈给模型厂商，得到的回复是「你们提示词写错了」。AYi 认为这是把工程缺陷包装成用户的技巧问题，把责任推给用户。
  • 第一条教训：别把安全寄托在系统提示词里写「请遵守安全规范」，提示词只是软约束，真正挡住攻击的是代码和权限。
  • 第二条：最小权限加沙箱（隔离的运行环境）——给 Agent 的每个 API 和数据库连接都限定只读或隔离范围，批量导出、删除、向外发数据这类操作必须停下来等人审批。
  • 第三条：AI 写的代码不能让同一个模型自己审，要经过静态代码扫描、自动化测试流水线（CI）和人工复核才能上线。

评论总结

  • 亮点HuntTheEdge 指出写代码的 Agent 和攻击的 Agent 用的是同一种能力；他的做法是只给 Agent 最小权限的密钥、生产数据库默认只读、上线前单独跑一个「红队」Agent 专门找漏洞。
  • 共识jeff20250405 和 0xm0reyu 都认为 AI 写的代码就是你自己的代码，出了事责任在签字上线的人，指望厂商负责是想多了。
  • 分歧Kiki9zpr 觉得这可能是早期版本的问题、新模型早修好了；AYi 回应说模型是按概率生成内容的，不可能有百分之百可靠的提示词约束，推理能力越强、绕过规则的能力也越强，与其等厂商修补，不如在自己的架构上设防。

Ben Horowitz 和 Gavin Baker 吵 AI 是不是泡沫：一个说借钱囤算力的「中间商」最危险，一个说 GPU 全在满负荷干活↗

AYi @AYi_AInotes7.4万 粉丝10月18日 23:04长帖

推荐原因把「AI 泡沫」争论里两派各自盯的指标讲清楚了；以后看算力公司或 AI 基建股的消息，可以直接用「债务是不是刚性、单价降得多快」判断谁最危险。

这条把三位投资人的说法放在一起。Ben Horowitz（硅谷风投 a16z 创始人之一）回忆：1999 年他创办云服务公司 Loudcloud 时，网络带宽每兆位要 1500 美元还买不到，只好签三年高价长约；两年后带宽跌到 50 美元，借钱囤带宽的公司还得按原价付钱，被活活拖垮。AYi 把这段历史套到今天：AI 模型按 token 收的调用费一直在降，但显卡、机房用地、电力和施工工人还在涨价，借钱买卡再出租算力的「中间层」公司两头受挤。Gavin Baker（科技基金经理）持反方：2000 年互联网泡沫顶峰时约 97% 的光纤埋在地下没用过，而今天几乎找不到闲置的顶级 GPU。FinanceYF5 另转 Horowitz 引用的 Databricks CEO 框架：AI 要「快速起飞」得同时满足四个条件，他认为目前一个都没实现。

核心要点

  • Horowitz 复盘的核心是「刚性负债配上浮动收入」：借钱买显卡要按固定利率还息、机房按长约交租，这些支出不会变；但租出去的算力价格随行就市，一旦新芯片或新算法让同样的活需要更少算力，租金下跌，现金流就先断。
  • 所谓套利（靠短期价差赚钱）撑不久：算力云厂商现在能收高租金，靠的是显卡短缺；短缺一缓解溢价就消失，借钱扩张最快的公司最先出问题——这就是「铲子最贵时借钱囤货，最先被埋的是转手铲子的人」。
  • Baker 的反方论据是利用率：当年光纤 97% 闲置，今天 GPU 几乎都在满负荷跑、甚至为散热和供电发愁，所以他认为不能把今天简单类比成 2000 年泡沫。
  • 「快速起飞」四个条件（转述 Databricks CEO Ali Ghodsi）：每代新模型所需 GPU 远少于上一代、训练时间更短、准确率更高，并且这三条趋势不断重复；Horowitz 的判断是目前一条都没做到，所以算力需求暂时不会突然塌掉。
  • 对你的意义：以后读到 GPU 租赁、算力短缺类新闻，与其看机房有多「烫」，不如看三件事——公司背了多少债和长约、算力单价降得多快、用量涨得能不能比单价降得快。AYi 个人押的拐点是端侧小模型（在手机或电脑本地跑的小模型）追上大模型，这只是他的推测。
